# TestJeff

JeffのJev互換APIをWindows / NVIDIA GPUで試す実験環境です。Pythonはこのフォルダの `.venv` のみを使います。公式 [firelex/jeff](https://github.com/firelex/jeff) を `vendor/jeff` に取得済みです。

## 文字風景判定・画像分類

[文字風景判定](http://127.0.0.1:8765/photos)と[画像分類](http://127.0.0.1:8765/classification)で、画像選択・ドロップ・フォルダ選択による一括処理ができます。画像分類は提供された `src/data/image_classification_definitions.json` の「画像全体の種類」9候補を大分類、「主な内容」63候補を小分類として独立に判定します。大分類で小分類候補を絞りません。副次分類・自由タグの推定は今回の二軸分類では行わず空配列です。

両ページの正常結果は `dev/feedback/images.sqlite3` の `image_results` に自動保存します。`thumbnail` 列は長辺240px以下のJPEGを埋め込むBLOBです。元画像は保存しません。ファイル名、判定日時、モデル、分類ID、確率、プロンプト、定義の版・ハッシュなどは列または `result_json` に保持します。SQLiteはGit対象外です。フォルダで失敗・対象外となった画像もエラー理由を記録しますが、読めない画像のサムネイルはありません。

「保存履歴」は両ページで分かれ、最新50件を表示し「以前の結果」で続きを読み込めます。再読み込み後も結果とサムネイルが残ります。履歴の拡大は保存済み縮小画像です。以前のサンプルJSON記録は保持し、自動移行はせず、新しく判定した結果からSQLiteへ保存します。履歴の時間はサーバーの推論時間で、ブラウザーだけで測った処理時間は画面・JSON出力に含まれます。

分類精度はモデル依存です。工事看板の5画像では大分類「その他」が多く、結果を正解とみなす精度評価は行っていません。

一覧の写真はクリック（またはフォーカスしてEnter）で拡大し、閉じるボタン・Esc・背景クリックで閉じられます。単画像のプレビューもクリックで拡大できます。

時間欄は「処理／推論」を表示します。処理は画像ヘッダー確認・ファイル読み込み・転送・サーバー側の準備・推論・応答受信を含み、最初の画像ではモデル準備も含みます。推論はサーバーでのモデル実行のみです。フォルダ処理の全体時間は一覧更新も含む経過時間です。保存済みサンプルに処理時間の記録がない場合は推論のみ表示します。

JPEG・PNG・WebPのヘッダーから解像度を確認し、1600万画素超は送信前に除外します。判別できない形式の最終検証はサーバーで行います。判定の間に意図的な待機は入れず、完了した行のみを更新します。

「フォルダの画像」の「フォルダを選択」で指定したフォルダ内のJPEG・PNG・WebPを、サブフォルダも含めて自動で一括判定します。選択中のモデル・編集済みプロンプトを使い、1枚ずつ処理します。読めない画像や容量超過は行ごとにエラーを表示して続行します。「停止」は現在の1枚の終了後に止まり、「再判定」は全件をやり直します。「結果を保存」で画像を含まない判定結果JSONをダウンロードできます。選択フォルダの表示はページ再読み込みで消えますが、保存履歴から判定結果とサムネイルを確認できます。フォルダ選択はブラウザー標準の選択画面を使います。

写真は選択または枠内へのドラッグ＆ドロップで自動判定します。「プロンプトを編集」で文字・風景・看板面積の指示を変更し「再判定」で反映できます。

「看板の推定面積割合」は、文字の画素ではなく文字看板の背景を含む面全体の割合を、0〜100%の10%刻みでモデルに選ばせます。文字存在確率とは別の値であり、領域検出・画素計測による実測ではありません。実例で大幅な過小推定が確認されており、正確な面積測定には使えません。

`dev/image` 直下のJPEG・PNG・WebPはページ下部に列挙され、「全サンプルを判定」で選択モデルと編集済みプロンプトを使って順番に処理します。結果・指示・モデル版・日時・画像ハッシュを `dev/feedback/photo-samples/` に保存します（各画像の最新1件）。再読み込みでも復元し、画像内容が変わった場合は旧結果を表示しません。各行の「モデル・保存結果」を開くと判定時のプロンプトを確認できます。サンプル画像と結果はGit対象外です。

[画像判定](http://127.0.0.1:8765/photos)で画像を選ぶと、Qwen 0.8B／2Bで自動判定します。「文字情報を含む写真」と「風景の写真」を独立に判定し、確率と応答時間を表示します。文字入りの風景は両方に該当し、人物や物だけの画像などは両方に該当しない場合があります。50%以上を「当てはまります」と表示します。モデルを変更すると同じ画像を再判定します。

JPEG・PNG・WebPを1枚、8MB・1600万画素まで受け付けます。サーバーで向きを補正し、長辺1024px以下に縮小して推論します。透明部分は白になります。原画像をディスクに保存したり、Codex／クラウドへ送信したりしません。サムネイルはSQLiteへ保存します。モデルはサーバー共通で、画像判定後は選択したQwenがロードされた状態になります。画像判定は`POST /testjeff/photos`、従来のテキストAPIの画像拒否は維持しています。

画像の文字を転記するOCR機能ではありません。細かい文字は縮小で見えにくくなる場合があります。判定はモデルの推定です。

## モデル対戦の操作

[モデル対戦](http://127.0.0.1:8765/battle)では、同じAと10個のBをローカル3モデルとGPT-5.6-Lunaの計4モデルで評価します。「対戦する」は入力中の名詞、「ランダム対戦」は抽選した組み合わせを使います。各候補の判定文章・確率・応答時間を横並びで表示し、最速の回答を青い枠で囲みます。確率の右には棒グラフを表示し、50%以上は緑、未満は赤にします。判定が割れた行は淡い黄色になります。並び順は元の順・名前順・判定が割れた順を選べます。

モデル別に平均・中央値・速度順位・最速件数・肯定数・平均確率・GPU確保量を表示します。4モデルの一致数は正解率ではありません。予備判定を各モデル1件ずつ行ってから10件を測り、予備判定とモデル切り替え時間は速度集計に含めません。切り替え時間には既にロード済みの場合もあり、モデルのロード速度比較には使いません。API応答時間はPC負荷等で変わります。

ローカル3モデルを順番に実行し、完了回数に応じて実行順を循環します。その後GPT-5.6-Lunaを実行します。終了・中止時は開始前のモデルへ戻します。他画面で同じサーバーのモデルを切り替えると対戦を中断する場合があります。中止は処理中の1件が終了した後に行います。

全40件に成功した回だけ、モデル別の累積件数・平均応答・最速件数と判定一致数をブラウザーへ保存します。既存の名詞判定の集計とは別です。「集計をリセット」で比較の集計だけ消せます。「結果をダウンロード」で今回の入力・結果・実行順・モデルの版・集計をJSONに出力できます。途中経過は画面を閉じると失われるため、必要ならダウンロードしてください。

GPT-5.6-Lunaはインストール済みCodex CLI（検証版0.156.1）を使い、`gpt-5.6-luna`・推論lowを固定指定します。Codexへのログインが必要で、対戦ごとに同じA/Bをクラウドへ送信します。予備1件と本評価10件の計11回を実行し、Codexの利用枠を使います。LunaはJSONの真偽だけを返し、Jeffの確率に相当する値は表示しません。Lunaの応答時間はCLI起動・クラウド通信込みです。ローカルモデルの純粋な推論速度との比較ではありません。

CLIはread-only・ephemeral・ユーザー設定非読込、shell/multi-agent/web search無効で実行します。`dev/temp/luna`を作業場所にし、入力はシェル文字列に埋め込まず標準入力で渡します。1件90秒でタイムアウトし、同時要求は409を返します。npm版Windows CLIを自動検出します。別配置なら`TESTJEFF_CODEX_EXE`に実体の絶対パスを指定してください。失敗時は代替モデルへ切り替えず、取得済み結果を保持して失敗を表示します。4モデルの累積は旧3モデルの履歴から分離しています。

呼び出し仕様は[公式の非対話モード](https://learn.chatgpt.com/docs/non-interactive-mode)と、実機CLIのヘルプで確認しました。

## 比較結果のユーザー評価

対戦が40件完了すると、比較表の「ユーザー評価」で各候補に「です」「ではありません」「判断困難」と理由を入力できます。入力に応じて、各モデルのユーザー判定との一致数・一致率を表示します。未評価・判断困難は一致率の分母から除外します。コメントだけの記録も可能です。

「評価を保存」を押すと、質問・候補・全モデルの結果・応答時間・版情報・評価コメントを`dev/feedback/knowledge.sqlite3`へ保存します。ブラウザーの集計リセットやサーバー再起動では消えません。ファイルはGit対象外です。次の対戦や入力変更で画面の評価欄は初期化されるので、必要な評価は先に保存してください。

「評価ナレッジをダウンロード」でJSONを取得できます。`latest`は対戦IDごとの最新評価、`history`は修正前を含む全履歴です。同じ保存要求の再送は重複させません。品質評価に使う場合はlatestを使用し、履歴を重複した試験ケースとして数えないでください。ユーザーの判定を基準とした一致率で、モデル学習への自動反映は行いません。

## 名詞判定の操作

画面上部にサーバープロセスのメモリ・GPUメモリ・CPU使用率を約2秒ごとに表示します。メモリはWindowsの物理メモリ使用量（Working Set）、CPUは区間のCPU時間を全論理CPU合計100%に換算します。GPUはPyTorchの使用量とキャッシュを含む確保量で、両者は加算しません。ドライバーなどのGPU使用量、ブラウザーと起動用親プロセスは含みません。取得失敗時は「取得不可」、CPU初回は「計測中」、CPU実行時のGPUは「未使用」です。非表示タブでは更新を休止します。

[名詞判定画面](http://127.0.0.1:8765/nouns)で「ランダム生成」を押すと、分類名から質問のA、1,000語から候補Bを10語抽選し、「これはAですか？」を全候補について自動評価します。候補Bは同じ回の中で重複しません。50%以上なら「『B』は『A』です」を緑、未満なら「『B』は『A』ではありません」を赤で表示します。「並び順」で名前順（日本語の文字列比較）、応答時間順（速い順）、判定結果順（「です」→「ではありません」→未評価・失敗）を選べます。選択するとすぐに並び替え、次の評価終了後も同じ方式を使います。同値は元の順序です。初期設定は応答時間順で、未評価・失敗は末尾です。名前順は読み仮名による五十音順ではありません。

各結果の「良かった」「悪かった」で、名詞・モデル・確率・判定文章・応答時間・評価日時とフィードバックを記録します。保存先は `dev/feedback/ratings.sqlite3`（Git対象外）で、ブラウザーを閉じても残ります。「記録をダウンロード」で全履歴をJSONとして取得できます。選択を変更すると変更履歴を追記し、同じ保存要求の再送は重複させません。同じresult_idの最後の記録が最新の選択です。記録はモデルの学習へ自動反映しません。

Aは自由入力（80文字以内）でき、「動物」「食べ物」「家具」「道具」「自然物」などの候補も選べます。Aや候補Bを編集して「評価する」を押してください。ランダム生成ではAも分類名から再抽選します。「中止」で以後の送信を止めます（サーバー側で開始済みの1件は完了する場合があります）。初期表示は「動物」に対する10語で、まだ評価していません。抽選は意味の関連性で絞らないため、無関係な組み合わせも出ます。

「モデル」でQwen 0.8B・Qwen 2B・Gemma E2Bを選択できます。旧モデルを解放してから読み込むため、同時常駐しません。切り替え中は入力と評価を止め、完了後に再び操作できます。モデルは同じサーバーを利用する画面全体で共通です。

ランダム生成が10件すべて正常完了するたび、モデル別に生成回数・累積件数・平均応答時間・平均「はい」確率を加算します。応答時間はブラウザーの送信開始からJSON受信まで（モデル読込時間は除外、推論の初回準備時間は含む）。各平均は累積合計÷累積件数です。中止・失敗した回、手動の「評価する」は加算しません。集計はブラウザー内に保存して再読み込み後も保持し、「集計をリセット」で選択モデルの分だけ消せます。

候補Bは [src/data/nouns.json](src/data/nouns.json) に25分類・各40語、計1,000語を収録しています。Aの入力候補とランダム抽選には [src/data/abstract-nouns.json](src/data/abstract-nouns.json) の分類名を使用します。辞書の分類は整理用で、推論の正解としては使いません。評価は選択したモデル名を明示して1件ずつ送信し、別の画面で途中にモデルを変更した場合はその回を集計しません。

## 起動

```powershell
cd C:\develop\test\TestJeff
pwsh -NoProfile -File .\dev\scripts\jeff.ps1 serve --model qwen-0.8b
```

起動後 [実験画面](http://127.0.0.1:8765) を開きます。日本語のサンプルボタンを選ぶと「状況」「質問」が入り、「判定する」で実行できます。「選択肢の順序」では通常判定と順序反転平均を切り替えられます。
モデルは名詞判定画面から切り替えられます。起動時に指定する場合は `Ctrl+C` で終了してから、次のいずれかで起動します。同じポートの二重起動は拒否します。

```powershell
pwsh -NoProfile -File .\dev\scripts\jeff.ps1 serve --model qwen-2b
pwsh -NoProfile -File .\dev\scripts\jeff.ps1 serve --model gemma-e2b
```

| 指定 | モデル | GPU空き容量の起動条件 |
|---|---|---|
| qwen-0.8b（既定） | Jeff-Qwen3.5-0.8B | 3GiB以上 |
| qwen-2b | Jeff-Qwen3.5-2B | 6GiB以上 |
| gemma-e2b | Jeff-Gemma4-E2B | 11GiB以上 |

空き容量は短文実験用の保守的な目安です。実測値は [検証結果](dev/testing/RESULTS.md) を参照してください。
GPUメモリ不足時は小さいモデルを使うか、起動時に `--device cpu` を付けます。CPU経路は用意していますが今回の実測対象外で、GPUより遅くなります。
1モデルずつ常駐、質問は1件ずつ推論、最大4質問、本文32KiBまで、画像なし。PyTorchの割り当て上限をGPU総容量の85%にしています。ほかのGPUアプリの使用量や入力長によってはメモリ不足になるため、その場合は503を返します。

## APIを試す

別のpwshで実行します。

```powershell
cd C:\develop\test\TestJeff
$request = @{
  model = 'jeff-latest'
  state = '近所のスーパーに歩いて行きます。外は雨が降っています。玄関には傘、サングラス、本があります。'
  questions = @{
    intent = @{
      type = 'choice'
      instructions = '雨にぬれないために、持っていくものを選んでください。'
      criteria = @{ '1' = '傘'; '2' = 'サングラス'; '3' = '本' }
    }
  }
} | ConvertTo-Json -Depth 8
Invoke-RestMethod http://127.0.0.1:8765/v1/systemone -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($request)) | ConvertTo-Json -Depth 10
```

`choice`は選択肢ごとの確率、`noul`は真である確率、`score`は定義した段階のスコアを返します。文章を生成するチャットAPIではありません。`model: jeff-latest` は現在起動中のモデルを指し、このフィールドを書き換えるだけではベースモデルは切り替わりません。

サンプルは [tests/requests.json](tests/requests.json) にあります。状況・質問・選択肢はすべて日本語です。APIのフィールド名と型名は規定のままです。

| 場面 | 判定すること |
|---|---|
| 雨の日の外出 | 雨にぬれないために持っていくもの |
| 帰り道の買い物 | 家族に頼まれた買い物 |
| 洗濯物が乾いた日のひと言 | 洗濯が終わったか、気持ち、伝えていること |
| 出かける前の鍵探し | 家族の話から最初に探す場所（順序反転も実施） |
| まだ届いていない荷物 | 配達完了の真偽（いいえ） |
| 電車に乗り遅れた朝 | 気持ちのスコア（不満） |
| いつもどおりの昼休み | 気持ちのスコア（中立） |

ブラウザーの全7サンプルとsmoke/verifyは、同じtests/requests.jsonを使用します。状況・質問・選択肢・結果の見出し・ボタン・接続状態は日本語です。真偽の両方向、気持ちの3段階、単一／複数質問、順序反転を試せます。APIのフィールド名・型名・JSONは仕様のまま維持しています。

## 再セットアップと検証

```powershell
cd C:\develop\test\TestJeff
pwsh -NoProfile -File .\dev\scripts\setup.ps1
pwsh -NoProfile -File .\dev\scripts\jeff.ps1 download --all
# 起動中のサーバーを停止してから、3モデルを順番に起動・API検証・終了する
pwsh -NoProfile -File .\dev\scripts\jeff.ps1 verify --all
# 起動済みのサーバーだけを調べる
pwsh -NoProfile -File .\dev\scripts\jeff.ps1 smoke
```

新規cloneには `git clone --recurse-submodules` を使います。モデルはGitには含まれません。ダウンロードは合計約15GB、CUDAライブラリ・キャッシュにも別途空き容量が必要です。モデルはmodels.jsonのリビジョンを使います。

`/health` は起動状態、`/v1/models` はAPI名、`/testjeff/status` は選択モデルとPyTorchのGPUメモリ実測を返します。`--port 8766` でポートを変えられます。待受は127.0.0.1のみです。
