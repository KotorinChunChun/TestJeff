# v0.18.0 問い合わせ件数と個別・一括速度比較

## 出典と目的

2026-10-04の会話で、対戦画面へのモデル別合計時間、質問の右に1・10・30・100件の選択、個別問い合わせと一括問い合わせの結果を保持して比較する画面が依頼された。

## 設計

- 既存対戦の件数を可変にし、入力済みのAとBを可能な範囲で保持する。従来の10件の履歴・集計を引き続き扱う。
- `/query-comparison` に比較画面を追加する。同じA・B・モデル・処理先で両方式を測定する。モデルは最大4列、未選択・計測不能を扱う。
- 各モデルの合計は最初の本問い合わせ送信から最後の応答受信までの経過時間。読み込みと各方式の予備判定は除外する。個別API応答時間の合計も別途JSONに保持する。
- 実行順を交互にし、入力・方式順・件数・実デバイス・モデル版・要求・実行条件・計測範囲を記録する。速度差は両方式が完了したモデルだけ算出する。
- 比較の個別・一括を共通のcomparison_idを持つ2件の対戦記録として既存SQLiteへ蓄積する。比較画面の履歴から両方を復元し、組のJSONをダウンロードできる。
- バックエンドは最大100件を検証し、結果数・評価注釈数の完全一致を確認する。Jeff/FDSの内部要求は最大8件ずつ。Lunaは可変件数の一括要求と出力検証に対応する。
- 100件の再現情報を省略せず保存できるよう、対戦・評価記録の上限を8MiBとする。一括のブラウザー待機期限は内部要求数に合わせて有限に延長する。
